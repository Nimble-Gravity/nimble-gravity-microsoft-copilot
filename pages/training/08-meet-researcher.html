Meet Researcher

Researcher is the first tool in this workshop you don't chat with — you brief it. It's a deep-research reasoning agent that plans a multi-step investigation across your work data and the web, then comes back with a structured, source-cited report. The run you commissioned in Module 1 is exactly this. This lesson is the spec sheet: what it is, what it can reach, which models drive it, and the operating facts that shape how you use it.

The Researcher Agent · ~15 min read
01 — What it is

A research analyst you commission

Generally available since June 2025, Researcher takes a brief, plans its own multi-step investigation, and delivers a structured report where every substantive claim carries a citation. The interaction model is delegation, not conversation — and that changes how you work with it.

The deliverable

A structured, cited report — headings, synthesis across sources, and links back to every file, email, meeting, or web page it drew from. Not a chat answer: a document you can review, challenge, and build on.

How you invoke it

Two doors, same agent: pick Researcher from the Agents list in the Microsoft 365 Copilot app, or type @Researcher in Copilot Chat. Either way, you're opening a mission, not a message.

It interviews you first

Before running, Researcher asks clarifying questions — scope, emphasis, exclusions. That's not friction; it's the agent doing intake like a good analyst would. Lesson 2 is about answering well.

🧭
The mental model shift

Chat is a colleague at your desk; Researcher is a colleague you send away for an hour. You invest more up front — a real brief, real answers to its questions — and you get back something closer to a finished workpaper than a reply.

02 — Reach & models

What it can see, and what thinks for it

Two dials define every run: the data it may reach, and the model configuration doing the reasoning. You set the first per mission; your admins set the ceiling on the second.

Reach

Work + web, scoped per run

Researcher can draw on the public web and your work data — files, mail, meetings, chats — plus Graph connectors, always within your existing permissions. You scope each run to work, web, or both. The Lighthouse mission used both: data-room files plus the Florida property market.

Same rule as Chat: it only sees what you can already open.
Models · 2026

The four-mode model picker

As of 2026, Researcher runs in one of four modes: Critique (the default — GPT drafts, Claude runs a second pass), Model Council (GPT and Claude in parallel, plus a comparison), GPT only, or Claude only. The Claude modes require your admins to have enabled Anthropic models in the tenant.

Critique is a strong default for finance work: a drafter and a reviewer, built in.
⚖️
Compliance aside — the EU Data Boundary

As of mid-2026, Anthropic-provided models are excluded from the Microsoft EU Data Boundary. For a US finance team that's context rather than a blocker — but if a workflow carries EU data-residency commitments, that's a question for IT before choosing a Claude mode.

03 — The operating facts

Four numbers and limits to plan around

Researcher has a real operating envelope — run times, a monthly budget, and a few current limitations. Knowing them is the difference between working with the agent and being surprised by it. All current as of Microsoft's FAQ, updated March 2026.

01
Runs take real time
Under 5 minutes for simple briefs; 10–45 minutes for complex ones like the Lighthouse mission. That's why the workshop's move is commission early, keep working — you started your run in Module 1 for exactly this reason.
02
25 queries a month
Researcher and Analyst share a pool of 25 queries per user per month, resetting on the 1st. That's a budget, and it rewards the well-briefed run — one strong mission beats three vague ones.
03
Text in, chat out — for now
Researcher can't read images inside input documents — charts pasted as pictures are invisible to it. And PowerPoint/PDF export of reports is listed as "coming"; today you copy the report out yourself, which Lesson 4 turns into a deliberate save-to-governed-files step.
04
Web scope is tenant-set
Which websites Researcher may or may not use is controlled by admin allow/block lists at the tenant level — you can't restrict sites per run. Steer sources through the brief instead: name the sources you want preferred.
04 — The horizon

Researcher that operates, not just reads

One roadmap item is worth knowing about, even though we won't use it today: Researcher with Computer Use, released to the Frontier early-access program around February 2026. It points at where agentic research is heading.

A temporary secure VM

Instead of only reading search results, Researcher gets a secure, temporary virtual machine where it can browse interactively and run code — then the machine is discarded when the run ends.

Gated sites, with your approval

It can sign in to gated sites — think subscription research portals — but only with your explicit approval at the moment of sign-in. The human stays in the loop at exactly the point that matters.

🔭
File under "watch," not "use"

This is a Frontier-program preview, not something to build a workflow on. If it reaches the tenant, the skills you're building today — briefing, scoping, citation review — transfer directly.
